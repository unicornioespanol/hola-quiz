# hola, quiz · América Latina

Минималистичная викторина на испанском: **HTML, CSS и JavaScript без React и без сборки**. Вопросы взяты из `Jovenes3_S10_Kahoot_velocidad_10preguntas.xlsx`: 10 вопросов, 4 варианта, по 20 секунд, уровень A2.

Сайт: [unicornioespanol.github.io/hola-quiz](https://unicornioespanol.github.io/hola-quiz/). Исходники: [unicornioespanol/hola-quiz](https://github.com/unicornioespanol/hola-quiz). GitHub Pages настроен с HTTPS. При изменениях GitHub автоматически проверяет игровую логику и подготовку статических файлов; публикация запускается вручную.

## Посмотреть локально

Из папки проекта:

```powershell
python -m http.server 4173
```

Открыть **http://localhost:4173**. Кнопка **Solo quiero practicar** работает сразу, без облачного проекта и установки npm-пакетов. Не открывайте `index.html` двойным щелчком: браузеру нужен HTTP для JavaScript-модулей.

## Подключить общую игру

GitHub Pages размещает статические файлы, а Supabase синхронизирует ведущего и телефоны. Проект `galnmhnhvdykiphyqzbc` уже подключён: созданы игровые таблицы, функции управления комнатами и загружены все 10 вопросов. В `config.js` записаны URL проекта и только публичный publishable key.

Выбран тариф **Supabase Free**. Управление базой выполняется через официальный Supabase MCP с OAuth: подключение `supabase` в пользовательском `~/.codex/config.toml` ограничено этим проектом. OAuth-данные хранятся локально средствами Codex и в репозиторий не входят. [Официальное описание подключения](https://supabase.com/docs/guides/ai-tools/mcp).

Если на Free проект долго не используется, Supabase может приостановить его: перед занятием следует проверить доступность и при необходимости восстановить проект в панели. [Правила приостановки Free](https://supabase.com/docs/guides/platform/free-project-pausing).

Следующие шаги нужны только при переносе сайта в **другой** проект Supabase; для действующего сайта настройка уже выполнена:

1. Создать проект в [Supabase](https://supabase.com/dashboard).
2. Открыть **SQL Editor** и выполнить сначала весь [supabase/schema.sql](supabase/schema.sql), затем весь [supabase/seed.sql](supabase/seed.sql).
3. В диалоге **Connect** найти **Project URL** и **Publishable key** (`sb_publishable_…`).
4. Заполнить [config.js](config.js):

   ```js
   window.QUIZ_CONFIG = {
     supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
     supabasePublishableKey: 'sb_publishable_YOUR_KEY',
   };
   ```

   Этот ключ предназначен для браузера и может быть в репозитории. Secret key и `service_role` здесь использовать нельзя. Для старого проекта также поддерживается публичный `anon` JWT.

5. После публикации открыть сайт на компьютере ведущего, нажать **Crear una partida**. На экране появятся QR-код и шестизначный код комнаты.
6. Ученики сканируют QR **один раз**, вводят имя и остаются на странице до конца игры. Приложение устанавливать не нужно.

В локальном тесте телефон не сможет открыть `localhost` компьютера. Для входа с телефонов используйте опубликованный HTTPS-адрес или IP компьютера в общей Wi-Fi-сети. QR всегда ведёт на текущий адрес сайта; для игры открывайте сайт ведущего по доступному телефонам адресу.

## Как проходит игра

- Ведущий создаёт комнату и видит имена подключившихся участников (до 100).
- Подключение открыто в лобби; после начала новые участники не добавляются. Уже вошедшие могут перезагрузить страницу и продолжить в том же браузере с прежними очками.
- Ведущий нажимает **Empezar**. Вопрос и четыре варианта появляются на телефонах. Устройства проверяют состояние комнаты примерно раз в секунду; отдельное WebSocket-соединение не требуется.
- Правильный ответ приносит от 1000 до 500 очков в зависимости от скорости. Неправильный и пропущенный — 0. Время приёма и баллы определяет сервер; повторный запрос не добавляет баллов.
- Разбор появляется по истечении 20 секунд, после ответов всех участников или по кнопке ведущего **Ver respuestas**. Следующий вопрос запускает ведущий.
- После каждого вопроса показаны распределение ответов и первые пять мест.
- В конце — полная таблица, общая точность, среднее время ответа, точность по каждому вопросу. Нажатие на имя открывает все ответы ученика с баллами и временем; на вопрос — распределение вариантов с именами и список пропустивших. Ведущий скачивает **CSV** с отдельной строкой на участника и вопрос, включая правильный вариант, баллы за вопрос и пропуски. CSV открывается в Excel.
- Вопросы и ключи ответов входят в статический сайт для режима практики. Это учебная игра, а не защищённая экзаменационная система.

Сессия сохраняется в браузере. Ученику не нужно повторно сканировать QR или вводить имя после перезагрузки в том же браузере. У ведущего раздел **Mis partidas** сохраняет до 30 последних комнат: после создания новой игры можно вернуться к прошлым отчётам. История доступна только в том браузере, где создавались комнаты. Комнаты доступны через приложение 7 дней; автоматического удаления результатов из базы нет. Для долговременного хранения отчёта скачайте CSV.

## Обновить сайт на GitHub Pages

Сайт настроен на публикацию из ветки `main` репозитория `unicornioespanol/hola-quiz`. Все ссылки относительные, адрес проекта GitHub Pages поддерживается.

1. Закоммитить и загрузить изменения в `main`.
2. Дождаться успешной проверки **Check quiz**.
3. В **Actions → Publish GitHub Pages → Run workflow** запустить публикацию. Источник GitHub Pages уже настроен на **GitHub Actions**.

Готовый [workflow](.github/workflows/pages.yml) публикует только `index.html`, `config.js`, `.nojekyll`, `assets/` и `js/`. Excel, SQL, инструменты и тесты в артефакт сайта не входят. Перед публикацией он проверяет наличие HTTPS URL Supabase и публичного ключа: пустую конфигурацию и secret/service_role он не пропускает. Автоматической публикации при каждом изменении нет.

Подготовить те же файлы локально: `python tools/package-site.py --require-live`. Для предварительного просмотра практики без облака: `python tools/package-site.py`. Результат — папка `dist/`.

## Обновить вопросы из Excel

```powershell
python tools/import-questions.py
```

Скрипт без внешних библиотек обновит `js/questions.js`, `supabase/questions.json` и `supabase/seed.sql`. Затем повторно выполнить `seed.sql` в Supabase. Менять вопросы следует между занятиями, когда нет активной игры.

## Проверки разработки

Для самого сайта npm не нужен. Для тестов:

```powershell
npm.cmd install
npm.cmd test
python -m unittest discover -s tests -p package_test.py
```

Тесты выполняют настоящие PostgreSQL-функции в PGlite: права ведущего, закрытый доступ к таблицам, таймер, имена, защита от повторных ответов, отсутствие раннего раскрытия баллов и полный цикл игры.

Браузерная проверка:

```powershell
npx.cmd playwright install chromium
npm.cmd run test:browser
```

В Windows вместо установки Chromium можно использовать установленный Edge:

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
npm.cmd run test:browser
```

Браузерный тест сам запускает локальный сервер с PostgreSQL-логикой, проходит практику и общую игру с ведущим и двумя независимыми участниками, проверяет перезагрузку, CSV и ширины телефонов 390/360 px. Скриншоты сохраняются в игнорируемую папку `test-results/`. Это проверка локального приложения; доступность реального проекта Supabase и игра на физических телефонах потребуют подключённого проекта.

Проверить тот же сценарий **на опубликованном сайте с настоящим Supabase**:

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
$env:QUIZ_BASE_URL='https://unicornioespanol.github.io/hola-quiz'
npm.cmd run test:browser
```

Этот режим не подменяет API и не использует локальную базу. Он создаёт тестовую комнату, проходит все десять вопросов с двумя независимыми браузерными сессиями, проверяет личные ответы, аналитику по вопросам, CSV и историю отчётов. Мобильные экраны эмулируются в браузере.

После подключения проекта: `npm.cmd run check:live`. Эта проверка обращается к **настоящему API Supabase**, создаёт тестовую комнату и двух участников, проходит все вопросы, проверяет права и итоговые данные, затем закрывает тестовую комнату.

В поставке только одна сторонняя браузерная библиотека: локальная копия QRCode.js (MIT), лицензия в `assets/qrcode.LICENSE`. Внешние шрифты, React, аналитические трекеры и CDN при открытии сайта не используются.
